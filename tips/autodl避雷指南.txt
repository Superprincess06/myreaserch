💰 一、 计费与扣费陷阱（护住钱包）
雷点 1：跑完忘记关机（最痛的领悟）

现象： 代码跑完了，但机器一直开着，第二天醒来发现卡里扣了好几十块钱。

对策： 养成好习惯，像我们之前聊的一样，在你的挂机脚本最后加上 shutdown 命令。或者在 AutoDL 控制台勾选“空闲自动关机”功能。

雷点 2：分不清“关机”和“释放实例”

现象： 关机后发现账号每天还在缓慢扣费（几毛钱到几块钱不等）。

真相： 关机只是停止了昂贵的显卡计费，但你的数据还保存在硬盘上，平台会收取微薄的“硬盘保管费”（通常是一天几毛钱）。只有点击释放实例，这台机器连同你的数据才会彻底销毁，完全停止扣费。

对策： 短期还会用，就只“关机”；项目彻底做完了，记得一定要“释放实例”并备份代码。

💾 二、 存储与硬盘陷阱（防爆盘）
雷点 3：把大数据集塞进系统盘

现象： 跑着跑着突然报错 No space left on device，机器卡死甚至无法开机。

真相： 默认开机后你所在的目录 /root 是系统盘，只有可怜的 30GB。装几个 Python 包、跑几个 Epoch 产生的缓存就能把它撑爆。

对策： 永远把数据集、模型权重和庞大的代码放在 /root/autodl-tmp 目录下！ 这是挂载的免费数据盘（通常有 50GB，还可以免费扩容），随便你怎么折腾。

雷点 4：跨地区找数据的绝望

现象： 昨天在【西北B区】上传了 10GB 数据，今天西北B区没卡了，去【北京A区】开个机，发现数据全没了。

真相： 各个地区的数据盘是物理隔离的，不互通！

对策： 尽量认准一两个常用的地区（比如常驻北京A区）。如果必须换区，建议用阿里云盘、百度网盘（AutoDL 有专门的网盘下载工具）作为数据中转站。

🌐 三、 环境与网络陷阱（防报错）
雷点 5：下载 GitHub 或 HuggingFace 模型慢到怀疑人生

现象： git clone 或者 pip install 一直卡住不动，最后 Timeout 报错。

真相： AutoDL 机器的公网环境访问部分外网资源受限。

对策： 开启 AutoDL 官方提供的学术加速！在终端输入这行魔法命令：source /etc/network_turbo。跑完网络请求后，再输入 unset http_proxy && unset https_proxy 关闭它（一定要关，否则有时会影响你代码内部的网络请求）。

雷点 6：CUDA 版本与显卡架构不匹配

现象： 租了极品神卡 RTX 4090，运行 import torch 直接报错，或者训练速度慢得像 CPU。

真相： 4090/5090 等较新的架构不支持老掉牙的 CUDA 版本（如 CUDA 10 或 11.3）。

对策： 新卡一律选择 PyTorch 2.x + CUDA 11.8（或以上版本） 的镜像。

⚙️ 四、 训练与运行陷阱（防中断）
雷点 7：终端断开，训练全毁

现象： 在 Jupyter 终端里直接输入 python train.py，跑了一半去上了个厕所，电脑休眠或者网页断开连接，回去一看，训练进程直接被杀死了。

真相： 这种运行方式叫“前台运行”，它与你当前的网页/SSH 连接绑定。连接一断，任务必死。

对策：

方法A（极客优选）： 学习使用 tmux 或 screen 命令，把任务挂在后台。

方法B（简单粗暴）： 使用 nohup 挂起进程。例如：nohup bash scripts/run_single.sh resnet50 > run.log 2>&1 &。这样就算关掉电脑，它也会在云端默默跑完。
